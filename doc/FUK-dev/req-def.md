# FUK (Fully Unexpected Keyboard) 要件定義（初版ドラフト）

## 1. 背景と動機

画面が小さいスマホのソフトキーボードでは、キーが小さく打ち間違いが多く、
ホームポジションに指を置けないためタイピング速度も劣る。
特に Termux 等のターミナル用途では、記号・修飾キーの入力負荷が高い。

これを解決するため、**画面全体を横方向に使った全画面・半透明キーボード**を
Android（ColorOS）上に自作する。キーボードを半透明にすることで、
裏側のアプリ画面（ターミナル上のカーソル・テキスト）を透かして見ながら
入力でき、「入力欄がキーボードに隠れる」問題を緩和する。

## 2. スコープ

### In
- Android IME（InputMethodService）としてのキーボードアプリ
- **横持ち専用**の全画面レイアウト
- **Unexpected Keyboard のフォーク**を土台とした開発（GPL-3.0 継承）
- 主用途：Termux 等のターミナルアプリでのプログラミング入力

### Out（本プロジェクトでは対応しない）
- 縦画面レイアウトの最適化（将来検討）
- 背後へのタッチ透過（IME の仕様上不可。AccessibilityService 方式は対象外）
- 音声入力・サジェスト／予測変換の高度な実装（既存機能の継承範囲に留める）
- タブレット・複数端末の最適化

## 3. 機能要件

| ID | 要件 |
|----|------|
| FR-1 | 横画面で**全画面幅**のキーボードを表示する |
| FR-2 | キーボードを**半透明**にし、キー越しに背後の文字（ターミナルのカーソル・テキスト）が読めること |
| FR-3 | `onComputeInsets()` により、背後アプリが**リサイズ・パンされない**こと（押し上げ防止） |
| FR-4 | `onEvaluateFullscreenMode()` で **extract mode（横画面の入力欄全画面化）を無効化**する |
| FR-5 | Termux 用途に必要なキーを備える：Ctrl / Esc / Tab / 矢印キー等（Unexpected Keyboard の既存機能を継承） |
| FR-6 | 既存配列（QWERTY＋スライド記号入力）を**横フル幅レイアウトに拡張**する |
| FR-7 | ColorOS 上で安定動作すること（IME プロセスがタスクキル等で不意に落ちない） |

## 4. 非機能要件

- **対応環境**：OPPO A5 2020 / Android 10 / ColorOS 7.1 を一次ターゲットとし、
  自端末＋近いバージョン（Android 10 前後）のみを検証対象とする
  （Android 11+ の WindowInsets 変更・edge-to-edge 強制対応は当面スコープ外とし、将来課題とする）
- **配布**：GitHub で OSS 公開。Unexpected Keyboard をフォークするため **GPL-3.0 を継承**する
- **性能**：キー入力の応答遅延は通常の IME と同等レベルを維持する

## 5. 制約事項・既知のリスク

1. **背後へのタッチ透過は不可**：IME ウィンドウは自領域のタッチをすべて受ける。
   半透明は「見えるだけ」であり、AccessibilityService オーバーレイ方式はスコープ外
2. **可読性のトレードオフ**：透明度を上げるとキー自体の視認性が下がる。
   キー越しに文字が読める透明度と、キーの判別性の両立が最大の設計課題
3. **入力欄が隠れる**：全画面化により背後アプリの入力欄がキーボード下に置かれる。
   FR-2 の透明性で緩和するが、プレビュー行等の追加設計も将来検討
4. **誤タッチ**：画面端のジェスチャーナビ・手のひら誤検知と端のキーの競合、
   マルチタッチ（同時押し）の取りこぼし対策が必要
5. **ColorOS 固有**：バックグラウンド制限による IME プロセス停止の可能性
   （自動起動・バッテリー最適化の除外設定を README 等に案内）
6. **アプリ側の制約**：縦固定アプリでは横持ちにならない、パスワード欄で IME が制限される等、
   IME として既存の制約は継承される
7. **実機が旧世代**：OPPO A5 2020（Android 10 / 720p LCD / 約 2.22:1 の横アスペクト比）で
   「画面全体を横に使う」効果がどの程度得られるか、PoC で実感を確認する

## 6. PoC（要素技術検証）

### 目的
「全画面・半透明・押し上げなし」のキーボードが本実機上で成立するかを、
最小改修で確認する。

### 検証方法
Unexpected Keyboard をフォークし、以下の最小改修を加えて実機にサイドロードする：
1. キーボードウィンドウの背景を透明化し、キー描画を半透明化
2. `onComputeInsets()` で contentTopInsets / visibleTopInsets を調整
3. `onEvaluateFullscreenMode()` で false を返す
4. レイアウトを横フル幅に拡張

### 判定基準
| ID | 項目 | 合格条件 |
|----|------|----------|
| PoC-1 | **ウィンドウ透過の可否** | Termux のテキスト・カーソルがキー越しに読み取れること |
| PoC-2 | **押し上げの回避** | キーボード表示中、Termux 側の画面がリサイズ・パンされないこと |
| PoC-3 | **ColorOS での安定性** | IME が使用中に落ちないこと。切り替え・バックグラウンド移行後に正常復帰すること |

### 検証アプリ
Termux（主用途のため）

### 検証手順
1. Termux 上でテキストを複数行入力しておく
2. FUK（PoC版）を有効化し、横持ちで全画面表示する
3. PoC-1〜3 の判定基準を確認する
4. 透明度を段階的に変更し、可読性が成立する閾値を観察する

## 7. 実装方針

- **土台**：Unexpected Keyboard（GPL-3.0）のフォーク
- **フェーズ 1**：PoC（本件）
- **フェーズ 2**：横フル幅レイアウトの作り込み、透明度設計の詰め
- **フェーズ 3**：Termux 実用での調整（修飾キー操作性、誤タッチ対策、README 整備）

## 8. 未決事項

- 半透明の具体的な透明度・配色設計（PoC の観察結果を受けて決定）
- 入力プレビュー（打った文字の確認方法）の要否
